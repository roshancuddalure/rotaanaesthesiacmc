# Companion reference integrity and absent facts

The companion now rebuilds supplied context before forwarding it to a local
model. For source-contract1, it checks the exact minimized constraints and
teaching features against both recorded content versions. Changed values,
duplicate/missing sources, unknown contracts, malformed flags and unexpected
versioned teaching/constraint data are rejected before inference. Boolean true
is not accepted as contract version1.

Only recognized integer/null limits, typed rest/staffing flags and ranges, and
known finite bounded numeric teaching components are forwarded. Arbitrary
top-level instruction/source-scope text, profile comments, omitted-fact claims
and unrecognized OT objects are not forwarded. The companion supplies its own
constant missing-fact list. This prevents a caller from relabeling a private or
instruction-bearing payload as ordinary reference metadata.

Legacy unversioned requests remain usable for existing clients and evaluation
tools, with recognized fields minimized and an explicit unversioned-scope label.
They acquire no source, currentness or authority claim. The current browser
requires the versioned backend contract before use. A caller who can construct
a matching content hash has not proved authorization or freshness: hashes are
content references, not signatures. Only normal authenticated application paths
and the final canonical validators carry operational authority.

## Missing-fact handling

Narrow factual-lookup patterns for unit OT demand, individual availability/
eligibility and private leave reasons receive a specific existing502 guard
response before any model call. Guidance points to the authorized OT calendar,
current candidates/postings/leave or leave records. Absence never means zero OT
demand, no leave, an available member, or a validated assignment.

General requests to balance duties while respecting OT or explain how approved
leave restricts replacement are retained. This is a bounded request gate, not a
complete natural-language classifier. It can require manual planning for some
questions and does not guarantee every paraphrase is recognized. No assistant
OT facts are fabricated; an actual minimized authoritative OT source contract
is still needed for richer factual answers.

## Verification and limits

`test_local_ai_reference_context.py` builds an actual backend reference envelope,
checks safe forwarding, content tampering, malformed flags/versions, private
features, metadata injection and missing-fact queries. It verifies rejected
inputs make zero model calls; general planning remains supported. Existing
claim/numeric/port/auth/outage/scorer/backend-minimization tests are included.
No operational DB, local-model inference, cloud traffic or assignment mutation
is used in these checks.
