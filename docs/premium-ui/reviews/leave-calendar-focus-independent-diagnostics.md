# Leave calendar focus: independent diagnostics

Reviewer `/root/remaining_icons_independent`, 28 October 2026. **Finding: v5's native horizontal focus reveal is insufficient. A bounded, owned horizontal RAF correction is a supported implementation candidate, not an integrated fix or acceptance.** No application, backend, service, database or acceptance ledger was changed by this reviewer. All experiments used explicit test-only injection into frozen preview 5201; none of those handlers exists in v5 application code.

## Actual defect and rejected approaches

The seven-column 49rem month scroller keeps status words readable, but native chronological Tab does not guarantee that its focused date is fully visible. At 320px, Chromium's May 13 button was at 258.84–368.28 within a region at 29–291, remaining clipped after the original three-second observation. Similar partial focus occurs in Firefox and WebKit. Checking only document overflow or the active element is insufficient; checking the target center is also weaker than full target/ring visibility.

The independent probes preserve all exact date controls and GET-only faithful fixture records. Three-engine comparisons rejected CSS scroll-padding/margin alone, an exaggerated margin, native mandatory/proximity snapping, and direct synchronous/one-frame reveal as a complete solution. The relevant raw reports remain in `tmp/leave-status-independent-focus-*.json`; these are diagnostics and their terminal zero does not mean every variant passed. Native `scrollend` exists in the three tested engines, but a single one-shot correction still failed Chromium root-200% geometry after browser placement. It is not sufficient as the production solution.

`leave-status-independent-focus-timeline.json` records the key ordering: initial May 1 focus was fully visible at approximately x49.7 with scrollLeft882, then the earlier native ArrowRight animation continued through later frames to x12.7/scrollLeft919 while focus stayed on the same button. A synchronous correction and a single RAF can both observe an initially fitting button before that subsequent movement. This explains why increasing a timeout or accepting partial focus would conceal the defect. Separately, WebKit truncated subpixel corrections: a 0.56px ring gap was left outside despite a nominal 4px margin. Outward integer rounding and a 5px correction allowance account for the actual two-pixel outline plus two-pixel offset without weakening the four-pixel visibility assertion.

## Bounded RAF experiment

The forced-unsupported RAF branch in `tmp/leave-status-independent-focus-owned-settle.json` passed **six contexts, 186 date controls**: Chromium/Firefox/WebKit, 320×900, normal/root-200% text. Every date retained exact chronological focus, complete horizontal target visibility and the full computed four-pixel focus ring. The first date required an actual owned completion record plus full geometry within three seconds; later dates required the same full geometry and owned RAF settlement. Two further browser frames were observed before recording rectangles. No maximum deadline was reached; observed settlement was at most approximately166.6ms.

This response-only candidate uses one focus owner, immediate horizontal reveal, then requestAnimationFrame checks until four stable scroll frames or a monotonic one-second deadline. Every callback requires the same active date, connected target/region, containment and no hidden/inert ancestor. It uses instant horizontal scrolling only, with outward rounding. It makes no focus call, vertical scroll, request, persisted state change or timer. AbortController cancels the pending owner on focusout and newer pointer, wheel or keydown intent.

The forced branch intentionally bypasses the available native scrollend feature; it therefore demonstrates a feature-independent path. Using that same bounded path for every engine avoids two production event paths with different failure modes. This is a candidate mechanism supported by experiments, not proof that a future helper already has equivalent code.

## Newer intent and disconnection

The final held test `premium-leave-status-focus-ownership-v4-independent-probe.browser.mjs` passed **15 contexts**, five scenarios in each engine: newer focus, native pointer intent, native wheel, native keydown and removal of the region. Exact source hashes were held, including the current record-workspace7c196c source. No corrective scroll ran after observed pending cancellation; newer focus was not stolen. Twelve cases recorded actual pending cancellation. Firefox's wheel case had already completed before the actual wheel event and correctly performed no later correction. Two disconnected-region cases stopped through the connected-owner guard without a focusout cancellation event; Chromium also emitted focusout on removal.

The pointer/wheel test records actual hit coordinates inside the visible focused date and capture-phase native event timestamps. A native pointer is followed by explicit test scrolling to represent manual intent; this is not a physical-device or real drag-scroll claim. The native wheel is dispatched through Playwright. Reports preserve which cases cancelled pending work versus encountered already-completed work.

Earlier harness failures remain preserved. The first ownership probe required cancellation even when a fast browser had completed before the next protocol action. A subsequent exact rerun legitimately failed its source-hold assertion when a concurrent reviewed record-workspace edit occurred. Another run used the region's top edge after native vertical reveal; the point could be outside the visible viewport, so the supposed manual input was not inside the region. V4 verifies the actual hit and actual event time rather than relaxing the no-later-correction condition. Its final run exited zero with source hashes held.

## Implementation and acceptance obligations

The application author should put the correction in a small frontend helper, install it only for the actual month scroller, and connect cleanup to its render/dispose lifecycle. Keep one owned pending operation per region, cancel old owners and RAF handles, abort listener resources when ownership is lost or the region disconnects, and retain all existing buttons, names, state and keyboard defaults. Prefer stability of the full target/scroller geometry as well as scrollLeft in production; that improvement requires fresh tests rather than inheriting this probe's pass. Do not add a global scroll watcher that snaps a manually panned calendar back to a still-focused day.

Source proof must explicitly disclose the new presentation listener/RAF/instant-scroll path; it must not retain a blanket claim that every event handler is unchanged. Add its instant motion classification and cleanup/error behavior. Test unsupported/throwing scrolling capability and owned failure recovery without inventing leave safety decisions or masking an unusable calendar. The existing Day list is the readable alternative.

After an actual helper proposal, repeat strict full target/ring predicates for all dates in all three engines, both themes, wide/narrow/short/root-enlarged contexts; native region scrolling; forward/reverse Tab; modal close and focus return; newer manual intent; hidden/disconnected/rerendered region cleanup; and all relevant leave data/toolbar/status regressions. Recheck computed focus ring bounds including ancestor clipping. These diagnostic matrices do not close original141/144/145/147, the full 260-item goal, physical-device checks or native assistive-technology checks.
