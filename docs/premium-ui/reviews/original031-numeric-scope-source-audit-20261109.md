## Proposed bounded runtime diagnostic

1. Freeze source hashes and exact application-served source identity before observations. Use the existing RAM fixture, intercept only specific GET response bodies for realistic category data, reject unexpected mutation requests, and preserve all other existing GETs. The completed-job fixture is already-saved server state, not injected UI.
2. Run Chromium, Firefox and WebKit sequentially at 320 and 1280 CSS pixels in light and dark schemes: 12 contexts. Navigate real routes and invoke actual controls. Never append representative numeric DOM nodes or call module functions through an injected button for the category proof.
3. Record exact API fixture values and existing rendered formatting before reading styles. For each actual numeric element, record text, DOM selector, category, `fontVariantNumeric`, computed font family, visibility, route, theme and viewport. Assert the space-separated computed value contains `tabular-nums`. Capture all applicable visible numeric children of the chosen table, not only its first cell.
4. Re-read text after style/geometry checks and assert equality; expected text must also be independently derived from fixture values and the existing display contract. Do not accept a before/after equality assertion alone if both strings could already be wrong.
5. Verify mobile card and desktop table instances separately. Expand real comparison/chart details through the summary and verify the actual table region remains reachable with no page-wide overflow. An intentionally horizontally scrolling table region is allowed.
6. Record denied unexpected requests, JS errors and source hashes again, and write observations even when assertions fail. Distinguish genuine computed failures from missing data, wrong selectors, route-loading failures and fixture-contract errors. No blanket requirement acceptance follows from the initial representative matrix.
7. Before acceptance, extend the classified instance inventory beyond the initial probes: member profile workload metrics; history/audit dates; analysis ranks/person tables and visual charts; leave dates and day counts; unit posting dates; review/publish slot counts; limits capacity and comparison tables; generation proposal/intelligence runtime and alternatives. Justify exceptions individually. The criterion explicitly disallows representative-only evidence for its broader scope.
