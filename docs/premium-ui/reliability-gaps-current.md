# Current frontend reliability acceptance gaps

Independent source/evidence review by `remaining_plan_review`, 21 October 2026. This is a gap assessment, not a new implementation plan or completion certificate. The approved 260-item scope remains intact. This reviewer made documentation changes only and independently ran the eight actual-source lifecycle unit tests successfully. Browser reports below belong to their recorded snapshots; this review did not rerun them. Physical checks remain pending at the user's direction.

Integration follow-up: central401 recovery, import/audit transport gaps and old error-body isolation have since received separately scoped independent acceptance in `reviews/session-expiry-current.json`. Four long-review visibility cases pass in `qa-sticky-review.json`. Those artifacts supersede the original findings below only for their stated coverage. Wider permissions changes, uncertain-save reconciliation, all-action acceptance and other sticky surfaces remain outstanding. The numbered source observations retain their original snapshot rather than being silently rewritten as current runtime failures.

1. **Session expiry and permission changes (197, 230).** `services/api.ts:request` protects against cross-tab token changes, including slow JSON decoding, but a current-session 401 or 403 only becomes a local `ApiRequestError`. A token can remain installed and the protected screen can remain interactive after expiry. Add one frontend expiry presentation/lifecycle that blocks repeated failed submissions, distinguishes expiry from role refusal, protects safe unsaved context, and never replays a mutation. Prove an expired in-flight save remains uncertain and that reauthentication requires deliberate resubmission. Do not treat the passing two-tab sign-out test as evidence for this different case.

2. **Mappings response ordering and recovery (184, 224, 225): integration fixed the source gap.** Initial inspection found unguarded global assignment and clearing useful rows on failure. The coordinator has since added `mappingLoadSequence`, captured-account checks, local-edit invalidation, preserved rows and escaped inline error/retry. I inspected those changes and two actual-source race tests; the stored Chromium report now has ten outcomes. Older Firefox/WebKit reports have eight editor outcomes each and do not yet prove the newer error/retry path. Keep a final source-matched race/recovery rerun and cross-engine recovery disposition rather than repeating the original defect claim.

3. **Month changes and import drafts (75, 136, 227): independent integration finding fixed.** Review caught the delegated `#leave-month` and `#unit-month` handlers ignoring the new central `applyWorkingMonth` false return and clearing drafts after a declined discard. The coordinator then changed all six legacy month branches to return before any cleanup when the decision is false. I inspected the corrected callers and independently ran `node --test tests/render-lifecycle.test.mjs`: eight tests pass, including an AST-extracted actual-handler test executing all six declined branches and verifying files/previews/resolutions/selections remain unchanged with no renderer/cleanup calls. This is stronger than the original central-function-only proof, but it is not a real browser file-picker preservation check. Remaining acceptance concerns other draft boundaries and browser file/mapping retention.

4. **Sign-out cleanup consistency (86, 225, 230): integration fixed the source gap.** The coordinator removed duplicate delegated sign-out and introduced shared `resetPrivateSessionView` for local/cross-tab cleanup. Inspection confirms mappings/imports/candidate contexts/selections and render generations are cleared. Existing stored session/shell outcomes cover bounded behavior; add a slow screen-load sign-out followed by another-role login if not already covered by final tests. Current-session expiry remains a separate gap in item 1 above.

5. **Uncertain saves are explained but not universally reconciled (93, 229, 243).** The shared helper correctly avoids mutation replay and warns when body decoding, network delivery or account change leaves the outcome uncertain. That is necessary, but the record-specific refresh/check path is not established for every editor. Map available existing GET/read-back capabilities to each affected save. Keep the original draft until the user chooses reconciliation, and disclose where the API cannot distinguish outcomes. Mocked read-back must stay labelled as frontend contract evidence.

6. **Stale data marking is incomplete (64, 226).** Several screens preserve useful data or cached optional summaries, but there is no complete register showing when each visible value was last confirmed or when its context became stale. Avoid introducing a decorative connected/saved indicator. Cover failed refresh after populated content and context change while an optional report is slow. Status must describe the evidence actually available.

7. **Action acceptance remains incomplete (3–7, 82, 140, 160, 180, 200, 258).** The inventory discovers 844 candidates; it does not certify 844 actions. Admin contracts explicitly record 147 runtime-pending candidates of 188. Other contract files contain “requires exact assertion mapping” entries. Classify true controls, structural fields and reference-only samples, then attach the existing exact assertions or add missing outcomes. Prioritize enabled destructive/import/publish/reversal/download controls. No enabled action may receive a pass just because its screen or module suite passed.

8. **Download failure and artifact checks need an explicit matrix (179, 186, 245).** Existing suites validate some download outcomes. A complete filename/format/nonempty/content/failure matrix is not supplied for every operational export and rejection report. Direct `fetch` download helpers also bypass the common request helper, so check expiry/account-change/cancellation behavior separately. No export content or backend contract change is authorized.

9. **Shared visual state reference is representative (16, 28, 40, 202).** The component reference demonstrates several real controls and eight tested theme/width combinations. It does not demonstrate every focus/hover/pressed/error/disabled/loading variant across all migrated components. Inventory remaining hard-coded and inline state colors; verify actual computed contrast and focus boundaries before deleting compatibility selectors. The 48 measured pairs do not prove every actual pairing.

10. **Sticky and keyboard occlusion evidence is narrower than screen reflow (52, 54, 139, 171, 208, 249).** The geometry suite checks shell breakpoint edges and text-spacing/forced-color navigation, plus one unit action. It does not measure every final import/proposal row and validation field against wrapped sticky-footer rectangles. Add focused bounding-box/scroll outcomes for the longest review forms at 320×568 and 844×390. Software-keyboard hardware behavior stays pending; do not infer it from viewport changes.

11. **Production asset failure matrix is incomplete (235, 236, 250).** Genuine missing recycle-bin chunk recovery and production GPU/CSP workflows pass in stored reports. Missing styles after ready, worker asset mismatches in old tabs, optional font/icon failure and hosting release-retention configuration need separate acceptance evidence. The bootstrap ignores errors once ready, so its initial-load recovery does not establish post-ready stylesheet recovery. Hosting settings are documentation dependencies, not permission to edit backend infrastructure.

12. **Measured performance and safe cleanup remain open (14, 115, 237–239).** Current build reports roughly 616 kB main JS and a conflicting static/dynamic extra-duty import warning. It also includes concurrent changes. Record repeatable render/long-task/layout-shift observations with representative large fixtures, then split only measured optional costs and remove dead paths only after proving action reachability. Bundle-size change alone does not establish an operational speed improvement.

13. **Role/context and browser coverage needs final reconciliation (12, 76, 197, 219, 251, 255).** The 144-case audit covers admin-like navigation states in Chromium. Mapping workflows additionally cover Firefox/WebKit. Neither proves all roles or every engine for generation, imports and account forms. Use authorized disposable or mocked fixtures, explicit unchanged payload assertions, and negative 403 outcomes; retain server permissions as authority.

14. **Release and review deliverables remain open (194, 256–260).** Current reports are individually useful, but not all cover the latest source hashes. Complete per-item five-perspective disposition, action evidence, reviewed screenshots, frontend rollback/review-build instructions and unresolved issues. Preserve historical reports; do not turn a newer review timestamp into a newer runtime pass. Deployment and push remain separate approvals.
